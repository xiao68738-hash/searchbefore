# 原生施藥輸入與本機提醒續作

## 範圍與限制

使用者要求補齊原生施藥／通知；同輪明確指定真實手機 Google 登入與雲端往返先跳過。這項驗收仍是待辦，不得改為通過。PR #148 維持草稿，release guard 不移除，不更新 Play 或真實雲端紀錄。

## 新增內容

- 實際每桶水量、本次總水量、製品總用量（mL/L/g/kg）、操作者、備註，可新增及修改；留空與明確 0 分開。不從試算自動建立施藥事实。
- 種子處理等無數字倍數用途也能記錄已發生的用量；不補造稀釋倍數，不把紀錄當用法建議。
- 數值與單位／長度驗證、舊視窗修改阻擋、原登記識別與未知欄位保留；報表增加實際用量摘要。
- 網站 farm-records.js 僅新增實際用量的明確白名單，仍剔除不明欄位。新版原生 JSON → 新版網站 → JSON 保留這些欄位；舊網站仍可能剔除，因此此相容變更須與原生發布協調。未包含 #147 的同步或分類程式改動。
- 本機提醒需使用者主動開啟，Android 13+ 另需通知權限；由 JobScheduler 約每日執行，無網路、無精準鬧鐘。系统省電／強制停止可能延後，不能依賴準時通知。
- 分田區用全部紀錄判斷；未知採收期優先，未指定田區逐筆處理。不受單筆 track/notify 隱藏偏好影響。提醒僅要求重新核對，不是「可以採收」。已知到期窗口為前 7 日至次日；未知項目檢查近 30 日紀錄，避免歷史資料永久重複通知。
- 通知不顯示作物、藥劑、操作者、帳號；不可變 PendingIntent 僅開本 APP 紀錄頁。服務僅接受 BIND_JOB_SERVICE 系統權限。
- 匯入／回復與登出會關閉提醒；關閉會取消排程及通知。資料修改／同步後撤掉舊通知並重新核對排程。通知偏好不匯入、不上傳；一天至多一次（使用者手動測試通知除外）。
- 新增 Android 通知與重開機排程所需權限，沒有加入相機、定位、儲存讀取或背景同步權限。
- AtomicFile 的讀寫及背景提醒讀取共用本機鎖，避免背景 readFully 與存檔競爭。

## 驗證

- Node 全套回歸通過；新增實際用量白名單往返、單位不符、科學記號、非數字、超量、過長與錯誤水量標記拒絕案例。
- JVM、Android 16（1.5 倍字型）及 Lint 正在重跑；結果完成後更新，不沿用前輪 39／5 的數字。
- Android 測試只在指定的唯讀模擬器，Google 登入跳過；通知測試僅更動預覽套件權限，使用隔離假資料／偏好，結束取消排程並還原權限。

## 仍待驗收

真實登入／雲端還原（使用者本輪要求跳過）、真實資料移轉、正式簽章、手機效能與完整無障礙、安裝更新保留資料。官方 TAP 固定表單不是本輪閱讀報表，仍需另做。
