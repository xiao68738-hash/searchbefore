## 零、安全紅線（不可協商）

這是一個**農友拿去決定今天要不要噴藥**的工具。錯誤不會當場報錯，而是幾週後變成殘留超標或違規。

1. **任何殘留／合法性結論，在人工確認前不得進 App 或資料管線。** 名稱查無、分類不明、任一層對照失敗時，只能標「無法確認」，**不得推論安全或違規**。
2. **不得由作物分類／群組外推合法性。** `PQC_SAFETY.directCropLevels` 刻意只回傳作物本身、不併入上層群組（官方逐項校驗完成前）。任何地方想「順便展開群組」都要先想清楚——這等於替農友做未經查證的合法性判斷。
3. **作物名查無時，不可只憑名稱近似逕自等同。** 見下方「胡麻事件」。
4. **安全採收期只能取保守值。** 一律經 `PQC_SAFETY.effectivePhi`，取「`phi` 欄位」與「備註天數」的**較長者**。全庫有 330 列兩者不同，其中 235 列若用原始 `phi` 會顯示**過短**的採收期，並經由「帶入計算／記施藥」污染採收倒數。
5. **文案不得出現**「安全／危險／高風險／保證合規／通過驗證／零風險／永久免費」等字眼。測試會擋，但別去繞過測試。
6. 混合劑：**任一成分於該作物缺標準**才成立「不得檢出」。

## 三、開發流程（違反會出事，都出過事）

1. **一個變更 = 一個獨立 PR，一律從最新 `origin/main` 開分支。**
   絕不在已開／可能已被 squash 合併的分支上追加 commit——會產生**永遠進不了 main 的孤兒 commit**。已發生過四次（#74、#75、#77，以及 #76 把胡麻的安全校正弄丟）。
   追加前先確認：`git log origin/main --oneline -3`。
2. **預設直接開下一個 PR**，假設使用者自行合併；不要問「要不要合併」。
3. **改 `index.html` 必須換版**：
   ```bash
   node scripts/bump-version.mjs 0.3.2.0 <slug>
   ```
   這支腳本一次改四處（`index.html` 的 `APP_VERSION`、`sw.js` 的 `CACHE_VERSION`、測試裡兩個釘住值）。**手動改容易漏**，漏了 `CACHE_VERSION` 會讓 PWA 續發舊快取——你電腦上看到更新了，農友那邊沒有，而且不會報錯。
   測試裡的版本 pin 要維持**跳脫點**格式（`/v0\.3\.1\.0-.../`），否則該腳本會拒絕執行。
4. 開新分支可用 `node scripts/new-branch.mjs`（或 `npm run branch`）。
5. **新增 `.js` 模組**要做完整儀式：script 標籤 + `sw.js` PRECACHE + `index-syntax.test.js` 斷言 + `run-all.js` 註冊 + 換版。
6. 提交前 `node tests/run-all.js` 全綠。以繁體中文溝通。

## 六、踩過的坑（**這節最值錢**）

### 1. 胡麻事件：不可擅自等同近似作物名
附表一**沒有「胡麻」**，卻同時有「**芝麻**」與「**亞麻籽**」兩個獨立項、容許量不同。台灣農藥慣以胡麻稱芝麻（Sesamum indicum），但中文亦可指亞麻籽（Linum）。

我曾逕自當成芝麻、把三筆改判「誤判／可刪」——那等於**刪掉真正該保留的不得檢出警告**。經使用者指正後全部退回「存疑」。

> **通則**：作物名查無時，先確認**登記證的真正作物身分**，再決定套哪一列。只有「同一作物不同寫法」（薏苡＝薏仁、葉用甘藷＝小葉菜類、檬果＝芒果）且無競爭項時才可等同。

### 2. 孤兒 commit
PR 被 squash 合併後又往同分支推 → 那些 commit 永遠進不了 main。**推之前先確認 PR 是否已合併。**

### 3. 深色模式：寫死 `#fff` 的卡片
新增元件若背景寫死白色而沒加 `html[data-theme="dark"]` 覆寫，深色下會變成淺字白底（實測對比 1.26:1，完全讀不到）。新增卡片類元件時，記得加進既有的 `background:var(--surface)` 覆寫群組。

### 4. `getComputedStyle` 在預覽面板的假象
用 JS 事後 `setAttribute("data-theme","dark")` 後，**靜態節點的 computed style 不會更新**（連 inline style 都不反映），會讓你以為 CSS 沒生效。正確做法：用 App 自己的主題偏好（`localStorage.displayPrefs.theme="dark"`）後**重新載入整份文件**再量。

### 5. 驗證資料時比對鍵要完整
比對藥劑列時 `agentKey` 含 `phi`。我漏了 `phi` 就出現 176 筆假差異，追下去才發現是自己配對錯。**先懷疑自己的比對方法，再懷疑資料。**

### 6. Service Worker 快取
本機驗證改版時，若沒清 SW 快取會一直看到舊頁面。清法：`getRegistrations().unregister()` + `caches.delete()` 後重新載入。

## 八、給接手者的建議順序

1. **先跑 `node tests/run-all.js`**，確認環境可用。
2. 讀 `mrl-data/資料夾索引.md`（MRL 全貌）與本文件第六節（坑）。
3. 若要動 App 功能：從**使用者回饋剩餘項**入手（點6「同成分不同商品不可視為相同」、點7「MRL 中性狀態文案」），這兩項不依賴任何人工確認。
4. **不要**在 MRL 人工確認（#3/#4/#5）完成前碰 #6/#7/#9——那些都建立在尚未查證的對照上。
5. 有疑義時**保守**：寧可標「無法確認」，不要猜。這個 App 的價值就是農友信得過它；被誤導一次，之後所有提示都會被忽略。
