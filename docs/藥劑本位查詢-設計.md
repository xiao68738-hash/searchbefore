# 藥劑本位查詢 — 資料面可行性與設計定案

現況查詢是**作物本位**（作物 → 防治對象 → 藥劑）。本文件是「**藥劑本位**」（藥劑 → 可用於哪些作物）的前置調查與設計定案，對應任務 #30，供 #31（查詢入口）／#32（結果頁）／#33（測試釋出）施工。

量測日期：2026-07-27。資料來源：`index.html` 內 `const DATA`（由 `scripts/build-data.mjs` 產生）。

---

## 一、結論：可行，且成本低

執行期建索引在瀏覽器只要 **11.5ms**（桌機 Chrome 中位值），記憶體只增 **2.15MB**（索引只存參照、不複製藥劑物件）。不需要預先產生索引檔，主檔不會變大。

## 四、設計定案

### 1. 索引在執行期建立，且延遲（lazy）建立
- 使用者第一次進入藥劑本位查詢時才建，**不拖慢首次開啟**。
- 建好後快取於記憶體；`DATA` 不變則不重建。
- 理由：11.5ms 的一次性成本，即使低階手機慢 5–10 倍（約 60–120ms）仍可接受；而預先產生要讓 5.3MB 主檔再加 0.24MB，且引入「索引與 DATA 不同步」的風險。

### 2. 索引只存參照，不複製資料
```js
byName  : Map<普通名稱, [{crop, pest, a}]>   // a 直接指向 DATA 內既有物件
byBrand : Map<商品名,  Set<普通名稱>>
```
**這個選擇消除了一整類 bug**：索引列與 `DATA` 是同一個物件，不可能出現倍數／採收期不一致。已驗證 17,333 列全數可由 `DATA[crop][pest]` 正向查回同一物件。

> #33 的「雙向一致性測試」因此改為**結構性保證的回歸測試**：只要有人日後改成複製資料，測試就會抓到。

### 3. 查詢 key：以「普通名稱」為入口，劑型／含量在結果內分層
- **564 個普通名稱**中有 **190 個**存在多種劑型／含量（最多者：勃激素A3 10 種、賽洛寧／益達胺／加保利／因滅汀各 7 種）。
- 入口若直接用「名稱\|劑型\|含量」（911 種）會讓使用者在還沒看到內容前就被迫選劑型 → **不合理**。
- 定案：**輸入比對普通名稱**；結果頁在每個作物底下，再依劑型／含量分列（沿用聯合防治的 `名稱|劑型|含量` 作為同一性判斷）。

### 4. 商品名可作為查詢入口（農民多記商品名）
- 6,039 個商品名中，只有 **6 個**對到多個普通名稱：
  粉好治→硫黃芬胺/二氟林、汰蟎樂→賜派芬/毆蟎多、速克菌→撲滅寧/貝芬替、
  除草靈→樂滅草/丁基拉草、勁熱情→三賽唑/嘉賜三賽唑（第6筆同類）。
- 歧義率 0.1%，**可安全支援商品名輸入**；命中歧義時列出對應的多個普通名稱讓使用者選，不自動挑一個。

### 5. 結果頁分組與上限（給 #32）
- 一律**依作物分組**；每組預設摺疊，顯示「作物名 · N 種用法」。
- 提供作物名篩選框（賽洛寧 87 作物需要）。
- 每列顯示：防治對象、稀釋倍數、安全採收期、登記來源、商品清單、作用機制。
- 欄位覆蓋率：`name/form/content/dilution/phi/dose/times/moa/note/bl` 皆 **100%**；`phiText` 僅 0.2%（例外註記，有才顯示）。

### 6. 安全界線（不可妥協）
- 只呈現該藥劑**實際登記**的作物，**絕不**由作物分類或群組外推。
- 文案須明確：**「本清單僅列有登記者；未列出不代表可以使用。」**
- 倍數與採收期一律照**該作物自己的登記值**，不跨作物套用。
- 沿用既有中性用語，不得出現「安全／危險／高風險」等像是系統做了專業判斷的字眼。
