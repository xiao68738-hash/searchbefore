# 官方資料更新：候選與正式資料分離

本流程不自動更改 index.html、原生 catalog、MRL白名單或Play版本。不使用私人紀錄。所有路徑以執行所在專案為基準。

## 1. 唯讀許可證差異

`node scripts/check-pesticide-update.mjs --out <新的證據目錄>`

退出0表示本次比較欄位相同；退出2表示有差異（不是抓取失敗）；其他錯誤必須調查。存下原始許可證與逐欄差異。許可證清單沒有變動，**不代表用法明細沒有變動**。

## 2. 完整獨立快照

`node scripts/fetch-pesticide-source.mjs --fresh-out <新的快照目錄>`

維持低併發6，不提高政府服務負載。不覆蓋舊快照。中斷後可用 `--resume-out <同一目錄>` 續抓；metadata會明確標記續抓，不能把最後完成時間冒充所有資料的取得時間。任何錯誤都不得視為完整成功。

## 3. 候選生成與差異審查

`node scripts/build-data.mjs --source-dir <快照目錄>`

`node scripts/compare-data.mjs --source-dir <快照目錄> --full`

建置前強制驗證分頁、唯一許可證及每一筆明細均有陣列結果；不把錯誤／缺漏當作無適用作物。此步只產生快照目錄的DATA.built.json，不更改正式資料。

逐項確認新增／移除／劑型／含量／用法／倍數／採收期／附註及商品名變動。單一許可證撤銷不等於整個成分全面禁用。不同用法不合併，特殊處理不產生虛構倍數。MRL與登記分開核對。

## 4. 發布前必要證據

- 全量來源快照雜湊與抓取限制。
- 候選差異報告及高風險欄位抽驗。
- 網站安全／分類／特殊用法／殘留提醒回歸；原生重新匯出資料與測試。
- 版本與資料日期分開更新；未完成使用範圍檢核不可只更新日期。
- PR審查、內部候選驗收後才發布；保留前版及可回復來源。
