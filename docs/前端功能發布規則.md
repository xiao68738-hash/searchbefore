# 前端功能發布規則

## 核心原則

尚未完善、尚未驗收或尚未完成正式串接的功能，預設不得出現在使用者前端。

目前的 `tap-workflow.js` 與 `tap-activity-mapping.js` 分別是資訊服務專員協作、特殊作業對照的內部狀態模型，只供開發與測試。它們不得載入 `index.html`、Service Worker 或正式 build；等官方代碼表、多人權限、分享同意、隱私文件與試辦驗收完成後，才能重新評估發布狀態。

若確實需要讓指定使用者試用，入口與功能內容都必須清楚標示「開發中」，不能只用「測試版」、「第一版」或模糊文案代替。

## 發布狀態

會建立前端入口、但需要分階段開放的功能，其狀態集中設定於 `service-config.js` 的 `features`：

- `hidden`：預設狀態。前端不建立入口，也不顯示功能內容。
- `development`：只供明確安排的測試。入口、標題及主要操作都要顯示「開發中」。
- `public`：完成驗收後正常公開，不再顯示開發標記。

設定缺少、拼錯或使用未知值時，一律視為 `hidden`，避免未完成功能意外露出。

純內部或後端模組不使用 `public/development` 切換；它們必須由正式構建排除，並以測試確認沒有進入 `index.html`、Service Worker 或發布檔案。`tap-workflow.js` 目前採此方式。

## 改成 public 前的最低檢查

1. 主要流程已能從入口走到完成結果，不依賴手動補救。
2. 錯誤、離線、權限不足及資料不完整時，有清楚且安全的處理方式。
3. 已通過對應的自動測試與人工手機操作測試。
4. 涉及農藥、MRL、採收安全或辨識結果時，不會把推測當成確定資訊。
5. 涉及個資、照片、雲端、付款或第三方服務時，已確認隱私、資安及平台政策。
6. 使用者看得懂功能用途、限制及資料會儲存在哪裡。

## 目前套用

`formOcr`（拍攝表單建立草稿）目前為 `hidden`。Google Cloud Vision 後端尚未完成部署、費用上限、隱私與實機驗收，因此正式前端不顯示入口。指定測試開始時才可改為 `development`，並須同時標示「測試中・開發中」、第三方雲端處理、逐次同意與人工確認；完成正確率及實際省工驗收前不得改為 `public`。
