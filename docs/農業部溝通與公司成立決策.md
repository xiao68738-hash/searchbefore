# 產銷履歷試辦：政府溝通與公司成立決策

本文件把「如何與主管機關談」、「如何避免和登打人員利益衝突」以及「何時需要成立公司」整理成可直接執行的方案。

更新日期：2026-08-01  
相關技術與試辦範圍：[產銷履歷串接-路線圖.md](產銷履歷串接-路線圖.md)

## 一、目前決策

1. 噴前查定位為**登打與輔導工作的增效工具**，不宣稱取代人員。
2. 第一輪只驗證「農民留下資料 → 系統整理草稿 → 人工覆核 → 仍由現行官方流程登打」。
3. OCR、規則或 AI 只能產生未確認草稿，不得自動寫入 L3。
4. 先取得制度與計酬方式的書面答覆，再承諾試辦不影響既有人員收入。
5. 現階段可由個人開發者進行詢問、訪談與免費小型試驗；出現正式收費、契約、採購或多人資料受託處理時，再成立有限公司。
6. 不主動倡議取消登打補助。若未來政策調整，應由主管機關依成效與公共利益決定。

## 二、先確認人員制度，不混用職稱

「資訊服務專員」、「登打員」與農糧署公開的「產銷履歷輔導員」不一定是同一身分、同一派案制度或同一筆預算。正式對外說明前要確認：

- 正式職稱與計畫依據。
- 派案與付費單位是農糧署、地方政府、農會、產銷班或其他組織。
- 計酬以戶、案、筆數、工時或完成驗證何者計算。
- 使用第三方工具整理草稿後，是否仍符合有效筆數、工時及期限規定。
- 哪些操作必須由農產品經營者、實名綁定人員或受授權人親自完成。

沒有書面答案前，對外只能說「希望不影響既有收入」，不能說「一定可以照常領取」。

## 三、與主管機關溝通順序

### 階段 A：制度確認

優先聯絡先前回覆 L3 API 問題的農糧署／系統介接窗口。這一階段不談採購，先確認：

- 第三方工具產生草稿、由人員覆核及人工登打是否可行。
- 使用工具是否影響派案、有效筆數或補助認列。
- 個人開發者能否作為系統開發方提出介接申請。
- 試辦應由哪個單位指導。

### 階段 B：小型流程試驗

在正式 API 上傳前，先用 1 位 L3 經營者、1 位實際登打人員及 3～5 位農民，處理 20～50 份既有紀錄。所有正式資料仍由現行官方流程人工登打。

### 階段 C：成果展示

至少整理下列數據，再向主管機關要求會議或示範場域：

- 每份紀錄處理時間的前後差異。
- 必填欄位缺漏率、人工修正率與補件次數。
- OCR 低信心或錯誤欄位比例。
- 登打人員能否在沒有開發者陪同下操作。
- 使用工具後是否影響人員可認列的案件、筆數或收入。

### 階段 D：正式合作

取得試辦證據與 L3 測試成果後，再討論第三方工具認可、擴大示範、機構授權、委託服務或政府採購。不在第一輪要求主管機關購買整套系統。

## 四、可直接寄出的確認信

**主旨：詢問第三方數位工具協助產銷履歷紀錄整理及登打作業之可行性**

> 承辦您好：
>
> 感謝先前說明產銷履歷 L3 系統介接申請方式。目前我規劃以一位已通過驗證並持有 L3 組織代碼的農產品經營者，作為第一階段介接及測試對象。
>
> 因實務上部分農民會由登打或輔導相關人員協助整理及輸入生產紀錄，我希望將工具定位為「紀錄整理與人工核對助手」，預計流程如下：
>
> 1. 農民以表單、拍照或簡易輸入留下原始紀錄。
> 2. 系統將資料整理為草稿，並標示缺漏或辨識信心不足的欄位。
> 3. 由登打人員或經授權人員逐筆核對與修正。
> 4. 經確認後才依核准方式登打或透過 L3 API 上傳；系統不會自行送出未確認資料。
>
> 為避免產品設計與現行制度衝突，想再請教：
>
> 1. 現行協助農友登打紀錄的人員，其正式職稱、計畫依據及計酬單位為何？
> 2. 使用第三方工具產生草稿，再由人員人工核對及登打，是否符合現行作業規定？
> 3. 使用輔助工具是否影響相關人員原有的派案、工時、有效筆數或計酬資格？
> 4. 農民建立草稿、受授權人員確認時，官方認定的登打人及登打時間為何？
> 5. 一位人員協助多位農產品經營者時，第三方系統在授權、帳號及操作紀錄方面須符合哪些要求？
> 6. 若先進行不涉及 API 正式上傳的小規模流程測試，建議由哪個單位或窗口提供指導？
> 7. 本人目前為個人開發者，提出 API 介接申請是否需要公司或商業登記？
> 8. 個別驗證的自然人農產品經營者如持有自己的 L3 組織代碼，是否可作為第一次 API 介接申請的測試對象，而不限定集團總部？
>
> 本工具的目的並非取代登打或輔導相關人員，而是希望降低重複抄寫、漏填及補件，並保留人工確認及操作歷程。若需要提供流程圖或安排簡短展示，我很樂意配合。
>
> 敬請協助說明，謝謝。

寄信時只附一頁流程圖或簡短功能說明，不附尚未完成的 OCR、L3 上傳畫面，也不宣稱已有官方合作。

## 五、公司成立判斷

### 現階段不必只為了訪談而成立

以下事項可先以個人身分進行：

- 免費封閉測試與使用者訪談。
- 尋找第一位已驗證且持有 L3 代碼的合作對象。
- 詢問 API、制度及測試資格。
- 進行不正式上傳的人工對照試驗。

是否能以個人開發者名義提出 L3 介接申請，仍需以上述第 7 題取得農糧署書面答覆。

### 出現任一條件時，啟動設立評估

- 即將向產銷班、農會、合作社或農民收取固定服務費。
- 需要開立統一發票、簽訂長期契約或投保。
- 要承接政府計畫、投標或接受機構採購。
- 要聘僱人員、分配股權或讓夥伴正式投入。
- 要受託保存多位農民資料、L3 回執或其他高責任資料。
- 對外承諾服務水準、資安維運或事故處理責任。

### 預設建議：一人有限公司

若噴前查確定商業化，預設優先評估有限公司，而不是行號：

- 公司具有法人身分，較容易區分個人與事業責任。
- 比較適合簽署軟體服務、資料處理及政府合作契約。
- 後續加入夥伴、處理智慧財產權及股權較清楚。

行號的設立與帳務可能較簡單，但負責人通常承擔無限責任。最後決定前，應請會計師確認稅籍、綠界款項、發票、營業項目及現有收入如何申報；若有夥伴，也應先書面確認程式著作權、資料、品牌與股權歸屬。

政府採購法對廠商採廣義定義，可能包含可提供服務的自然人；但每一案件仍可另定投標資格。因此「法律上不一定非公司不可」不等於「實務上不需要公司」。

## 六、成立前就要完成的治理文件

- 試用合作同意書與退出方式。
- 農民資料使用及隱私告知。
- 表單照片蒐集、去識別化與刪除期限。
- 每位農產品經營者對登打人員的明示授權及撤銷紀錄。
- 角色權限、修改歷程與人工確認紀錄。
- 不索取、不共用及不代管 L3 密碼的規則。
- 系統只產生草稿、人工確認後才正式登打的責任界線。
- 合作結束後資料匯出、移交與刪除程序。

## 七、90 天執行表

| 時間 | 行動 | 完成條件 |
|---|---|---|
| 第 1～2 週 | 寄出確認信；訪談 1 位實際登打人員；尋找 L3 合作對象 | 取得窗口回覆、確認人員正式身分與一位候選夥伴 |
| 第 3～4 週 | 準備介接申請；建立去識別化試驗資料與人工核對表 | 申請資料可送件，試驗不含正式自動上傳 |
| 第 5～8 週 | 比較 20～50 份紀錄的原流程與輔助流程 | 有時間、錯誤、修正、補件與使用意願數據 |
| 第 9～12 週 | 整理試點成果並向主管機關展示 | 取得是否擴大試辦及是否需要事業登記的明確下一步 |
