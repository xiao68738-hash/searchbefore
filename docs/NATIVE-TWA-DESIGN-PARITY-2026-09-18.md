# 原生與 TWA 設計一致性

## 使用者決策與範圍

使用者指出 v6 與原 TWA 美編差異巨大，確認以原 TWA 為設計基準。此次是原生 Compose 版面／導覽調整，不更改 Firebase、資料 schema、登入同步授權或 Play 軌道。手機現有 Play v6 保留，先使用獨立模擬器驗證。

參考：index.html 的既有樣式及 releases/play-store-screenshots-20260917 的實機查詢／登記卡片，不生成假 APP 圖。

## 第一輪調整

| 原 TWA 設計 | 原生處理 |
|---|---|
| 深綠品牌頁首、米白頁底 | 色值對齊；保留內部／預覽標記及資料移轉入口 |
| 查詢、計算、配方、倒數、紀錄、個人 | 還原六個入口；農務放入紀錄內，沒有刪掉原功能 |
| 兩個大型查詢模式鈕、編號步驟 | 以作物找藥／以藥劑找作物；選作物→選病蟲害→查看登記 |
| 大字藥名、商品名、劑型／作用機制標籤 | 重排既有欄位、白底數值區，不新增或改寫用藥資料 |
| 查詢帶入計算 | 同一登記 ID＋採收型態帶入；不能任意輸入倍數，特殊用法仍被阻擋 |
| 倒數入口 | 沿用 Backup.harvestDate，未知不當零天，已到期不等於可採收／殘留合格 |
| 切換不必重查 | SaveableStateHolder 保留各分頁查詢狀態；計算選取 ID／型態也可還原 |

## 驗收與限制

最終程式重新建置成功（3m12s），56 JVM／0 failures／0 errors，Lint `No issues found.`。獨立 Android16（emulator-5580，720×1280／320dpi，1.5 倍字體）完整 14 項 UI 測試通過（51.523s），涵蓋新六分頁、原登記／相關導引分開、分頁與 activity 重建後保留查詢／計算、捲動位置、型態不適用阻擋計算、警語、通知與隔離儲存。一般字體另有 4 項導覽測試通過（TestRunner 01:18:02 UTC：4 tests, 0 failed）。沒有對手機跑 instrumentation。

視覺複核曾發現查詢捲動後頁首／分頁被內容蓋住，原本僅驗元件存在的測試沒有捕捉。已明確設定 adjustResize 並將內容區 clipToBounds；新增真實視窗截圖的品牌頁首像素斷言，搭配分頁可見檢查。最終一般字體 home.png／registered-use.png 已人工看圖確認頁首、卡片及底部分頁可見。長文字字級與換行仍可細修，不能僅憑元件測試宣稱美編完成。

最初模擬器開機曾出現 System UI 無回應，crash buffer 另有開機階段 Google Play services SIGABRT；等待恢復後正常顯示 APP，再完成上述全套測試。不能把這次成功說成環境或正式版長期零當機。

預覽圖位於本機 `D:/SearchBefore/audits/native-twa-parity-20260918/`，僅公開查詢画面；不包含使用者雲端資料。此次不發布 AAB，不把預覽截圖當成已上架版本。

第一輪不是全頁像素級一致：原生仍用系統字型（未下載新字型），資料移轉／內部標記與 TWA 不同。紀錄／個人頁細節、顯示偏好、完整操作一致性仍需後續核對。不得宣稱全面取代已完成。

## 第二輪：桶數換算與倒數日曆

- 計算頁增加每桶水量、整數桶數、每桶藥量、總水量及總藥量；採原登記稀釋規則。拒絕非正整數桶數、超界總水量、科學記號與不適用型態。桶數是現場輸入，不是推薦施用量。
- 常用配方依既有 schema 只保存每桶水量；本次桶數不存入配方，也不自動建立施藥紀錄。面積模式與多藥批次仍未完成，不假設每公頃用水量。
- 倒數增加清單／日曆切換、上下月與逐日明細；顯示施藥日，以及同田區最晚的「等待期到期參考」。任一筆未知採收期就阻擋該田區到期事件，仍保留其施藥事件，不把空白日當可採收。
- 未指定田區的紀錄只作單筆參考。刻意不沿用 TWA 將同作物但未指定田區合併的舊 fallback，避免推定兩筆資料來自同田區；與原生既有提醒分組方向一致。未改原生通知政策或新增日曆存取權限。
- 日曆日期觸控目標至少48dp；窄螢幕允許水平捲動。採收期未知文字降為18sp，避免窄卡片只剩一個字換行，仍隨系統字體放大。
- 本輪僅本機開發與隔離模擬器驗證，不修改手機 Play v6、雲端資料或任何測試／正式發布軌道。
