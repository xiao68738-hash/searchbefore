# 農藥抗藥性與系統性標記：後端先行架構

## 目標

先建立不影響正式查詢畫面的資料契約與分類函式，讓後續查詢系統可以：

1. 篩出高／中高抗藥性風險的作用機制。
2. 以「系統性、選擇系統性、局部系統性、非系統性、待確認」簡單標記藥劑。
3. 保留穿層滲透與上下移行欄位，日後資料補齊時不用改 API。

資料基準為《農用藥劑分類及作用機制檢索（第四版）》（112 年 1 月）。本階段不把 PDF 放入 repository，只保存經人工核對的事實型目錄、頁碼與版本資訊。

## 資料邊界

- 抗藥性風險是「作用機制代碼」層級，可套用到現有 `entry.moa`。
- 系統性是「有效成分」層級，以 `entry.name` 查表，不從 IRAC／FRAC／HRAC 代碼推論。
- `unknown` 與 `non_systemic` 必須分開。資料未收錄、PDF 未標示或名稱比對失敗時，一律為 `unknown`。
- `highResistanceRiskOnly` 目前把 `high` 與 `medium_high` 納入；可由 catalog policy 調整。
- 這是抗藥性管理提示，不是對特定田區、病蟲害或產品效果的診斷。

## 檔案

| 檔案 | 用途 |
|---|---|
| `mrl-data/pesticide-classification/catalog-v1.json` | 版本化來源、風險規則與有效成分移行特性 |
| `scripts/pesticide-classification.mjs` | 正規化、分類、篩選與涵蓋率統計 |
| `tests/pesticide-classification.test.js` | 資料契約與安全邊界測試 |

移行特性紀錄另回傳 `confidence` 與 `sourceReference`。目前信心水準區分為文件直接圖示、文件直接接觸活性分類、人工核對無圖示，以及尚未驗證；前端不得把後兩者混成同一種確定程度。

## 回傳範例

```js
classifyPesticide({ name: "益達胺", moa: "IRAC 4A" })
// {
//   resistanceRisk: { level: "high", label: "高", isHighRisk: true, ... },
//   movement: { movement: "systemic", label: "系統性", isSystemic: true,
//               confidence: "direct_document_marker", sourceReference: ..., ... }
// }
```

## 併入查詢系統前的工作

1. 用現有 `DATA` 跑涵蓋率報告，列出未分類但使用頻率高的有效成分。
2. 人工補核第四版中穿層滲透、上下移行與沒有系統性標記的成分；沒有圖示不得自動當作非系統性。
3. 名稱比對增加英文名與同義名，但不得用商品名直接推論有效成分。
4. 前端先顯示標籤與說明，再加入篩選器；`unknown` 必須可見。
5. 後續更新新版 IRAC／FRAC／HRAC 或官方資料時，保留來源版本與變更稽核。

## 建議顯示文字

- 高風險：`抗藥性風險高；請輪替不同作用機制，並依標示與專業建議用藥。`
- 系統性：`可在植物組織內移行；實際施用方式與安全採收期仍以產品標示為準。`
- 非系統性：`本資料標示為非系統性；需注意藥液覆蓋與接觸位置。`
- 待確認：`本版資料尚未完成此特性分類，請勿據此推論用法。`
