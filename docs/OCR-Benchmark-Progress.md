## 判讀限制

- NAF v1 的 `transcriptions` 已確認含 field-level 人工文字答案；40份文件共376個轉錄欄位、4,134字元、811詞。它們與列×欄交集結構cell分層保存，不將無法幾何對齊的欄位誤標成表格cell。
- ML Kit 是文字辨識器，不提供 cell/table 結構；結構指標不能直接與 Document AI、Azure 對等比較。
- 原始圖片、供應商回應及辨識文字只可存放於 `D:\SearchBefore\private`。

## 首張繁中真實表單

表13實拍樣本的兩個手寫欄位已由使用者確認：資材名稱為「蘇力菌」，第一列日期為「7/14」。ML Kit全圖輸出將前者辨識為「教角」，後者沒有輸出；2欄field-level結果為完全符合率0%、CER 100%、有輸出率50%。單欄裁切、3倍放大、灰階對比與固定閾值亦未救回正確文字。這只是第一張、兩個欄位的基準，不代表繁中表單整體準確率；目前必須維持人工核對，且不得自動填表。

2026-08-26 追加欄位分流實驗：依全圖文字座標重新裁出資材名稱與日期欄，分別使用 ML Kit Chinese、ML Kit Latin 及 Windows.Media.Ocr `zh-Hant-TW`，並比較原圖、3倍放大、灰階對比、固定閾值與 ±4°／±8° 小角度校正。所有組合仍沒有任何欄位完全符合；日期在較寬裁切的 Latin 模型最多只讀出「7」，緊密裁切及旋轉後反而漏字；名稱的旋轉候選仍為「教角」、「欢依」等錯字。這證明目前不能用「多跑幾個變體再挑一個」假裝提升準確率，也不能靠字典把低證據輸出直接改成「蘇力菌」。變體評分報告明確標為 development-only oracle，產品端仍只建立待人工確認草稿。

2026-08-26 新增本機人工校正閉環：OCR 開發介面的單筆審查畫面在使用者完成必要核對後，可主動下載 `ocr-local-correction` JSON。資料只含允許欄位的 OCR 候選、信心值、人工確認值與 exact-match 結果；不含影像、原始全文、來源檔名、請求識別碼、帳號、執行人或田區代號，不寫入瀏覽器儲存空間，也不自動上傳。這份資料可作為後續擴充真實繁中 field-level ground truth 與迴歸評估的輸入，但欄位文字仍可能包含農務內容，對外分享前必須人工檢查。

同日完成私有校正檔彙整工具 `scripts/aggregate-private-ocr-corrections.mjs`：輸入與輸出被限制在 `D:\SearchBefore\private`，逐檔檢查 schema、隱私宣告、禁止欄位、大小與重複 correction ID，再彙整各欄位的 exact-match／output rate。任何含影像內容、來源檔名、request ID、帳號、執行人或田區代號的檔案都會被拒絕；彙整結果明確標記不可公開。

2026-08-27 乾淨模擬器重測：將 API 34 AVD 清空資料並冷開機，重新安裝主程式與 instrumentation APK。合成白紙＋三層表格的品質測試通過，確認白色紙面不再被當成反光，垂直堆疊的表格區塊不再被誤判為多份文件。相同實拍原圖、欄位裁切、對比及 ±4°／±8° 版本以 ML Kit Chinese／Latin 重跑後，共32次欄位嘗試仍為0個完全符合；結果保存於私有 `retest-2026-08-27/field-report.json`。因此本輪改善只可描述為品質閘門與錯誤抑制提升，不能描述為手寫辨識準確率提升。

原型現在同時執行 Chinese 主模型與 Latin 數字輔助模型；只有日期、稀釋倍數、用量與安全採收期等數字欄位可採輔助模型證據。兩模型衝突時雙方信心皆壓到自動選取門檻以下；只辨到月／日時保留 `MM/DD` 待人工補年份，不推測年份。資材名稱僅在「資材名稱」標籤附近允許編輯距離1的字典候選，仍不得自動選取。

2026-08-28 追加三組受控實驗，均未改善完全符合率：

- 手寫區焦點裁切：日期移除印刷標題、資材名稱縮小到填寫區，Chinese／Latin 共24次推論仍為0/2；日期全空，名稱最佳只剩標點。裁切失去模型所需脈絡，不採用。
- 近水平表格線抑制：以 NumPy 的受限 Hough-style 搜尋，只移除覆蓋至少58%欄寬且斜率在±0.16內的線，避免把日期斜線當表格線。12次推論仍為0/2，不接產品；工具保留供未來引擎比較。
- Microsoft `trocr-small-handwritten`：在隔離 CPU 環境對17個日期版本本機推論，模型約247 MB，影像未上傳。所有輸出皆為空值、英文詞句或重複數字，沒有「7/14」。官方模型以英文手寫資料為主，不適合本案，也不加入 Android。runner 為 `scripts/run-trocr-date-benchmark.py`，輸入與輸出皆強制限制在 `D:\SearchBefore\private`。

以上實驗再次證明，不得用格式限制強迫模型輸出合法日期，也不得用已知正解挑選預處理版本。下一個有效資訊必須來自更多不同筆跡的實拍 ground truth，或具繁中手寫能力且完成隱私評估的引擎。

三方 benchmark 完成狀態：ML Kit已完成；Document AI與Azure未完成，仍不得對外宣稱已完成三方比較。
