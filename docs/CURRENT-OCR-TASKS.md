## 獨立 holdout 驗證

從同一 NAF 官方 test／valid 資料中排除原40份後，取得21份完全未參與門檻調整的文件，共1,842個cell、12個來源群組。固定既有參數後重跑：v6為precision 11.02%、recall 22.04%、F1 14.69%、表格偵測率76.19%；v8為precision 11.43%、recall 25.90%、F1 15.86%、表格偵測率90.48%。v9沒有任何頁面同時符合相似度、格數差及格線支撐條件，因此結果與v8相同。主要失敗型態是低格數真實表格被正文或其他線條產生的數百個候選淹沒。此驗證未通過，原40份迭代結果只能用於開發比較。

## Projection 信心閘門 v10 結果

v10 只處理 v5 projection 補救產生的候選，不改動直接格線、區域格線、雙頁共識、方向補救及同卷宗轉移。閘門依 projection 欄寬變異、目標頁格線支撐及影像長寬比決定保留或拒絕。在50份低複雜度 train 開發集上，false positive由7,656降至2,131，precision由9.90%升至18.54%，recall由16.20%降至9.34%，F1由12.29%微升至12.42%。原40份迭代集的3份 projection 文件均通過，v9結果維持不變。

固定規則後重跑21份驗證集，false positive由3,696降至1,045，precision由11.43%升至24.60%，recall由25.90%降至18.51%，F1由15.86%升至21.13%，表格偵測率由90.48%降至66.67%。這顯示信心閘門能跨資料降低假格，但屬偏保守模式，漏檢風險仍高。

## 方向補救信心閘門 v11 結果

v11 只處理經 v10 拒絕後仍為空結果的頁面，重新取得 v8 的方向候選，再以目標影像格線邊緣支撐、格寬／格高變異、候選格數與水平覆蓋率決定是否恢復。50份低複雜度 train 開發集由 v10 的 precision 18.54%、recall 9.34%、F1 12.42%、偵測率30%提升為30.22%、20.71%、24.58%、48%。

規則固定後，21份holdout只恢復1頁：true positive由341增至356、false positive由1,045增至1,051；precision由24.60%升至25.30%、recall由18.51%升至19.33%、F1由21.13%升至21.91%、偵測率由66.67%升至71.43%。原40份開發集沒有恢復任何頁面，v10成績維持不變。這是目前第一個在train與holdout同時提高precision、recall及F1的空頁補救，但絕對準確度仍低，不得上線自動填表。

## NAF 文字 ground truth 與本機比較基準

NAF 每份標註的 `transcriptions` 實際包含 `fieldBBs` 對應文字。現已保留40份文件的全部376個有答案欄位（4,134字元、811詞），並輸出逐欄位crop與CER／WER評分器。列×欄交集結構cell和轉錄欄位不是同一套幾何標註，因此兩者分層保存，只以空間重疊建立可追溯連結，沒有將無法對齊的欄位硬塞入結構cell。

Windows.Media.Ocr `en-US` 僅作本機管線檢查：原始crop的辨識欄位率22.87%、exact field rate 4.26%、CER 95.79%、WER 108.38%，不合格。放大、對比強化、固定閾值二值化都未改善CER（分別97.22%、96.78%、98.45%），故不採用。這些數字不代表 ML Kit、Document AI、Azure；指定三方仍須各自實跑。

Google ML Kit Latin 16.0.1 已在Android 14 API 34模擬器完成同一批376欄位：原圖CER 93.93%、WER 107.77%、完全符合率7.45%、有文字輸出率34.31%、平均每欄421ms；其中2個小於32像素的crop被模型拒絕。3倍放大CER 93.90%但有輸出率降至32.45%、平均535ms；對比強化CER 98.21%；固定閾值二值化CER 101.96%。原圖仍為最佳實驗基線，但絕對準確度不合格。
